\### О проекте

Это полноценный микросервисный OCR-пайплайн для распознавания метрических книг. Вся система запускается через Docker Compose и состоит из пяти сервисов: распознавание текста, сегментация таблиц, LLM-постобработка (GigaChat), оркестратор и фронтенд.



\##Как настроить перед запуском

Самое главное — получить ключ GigaChat. Зайди в личный кабинет GigaChat API, скопируй credentials. Затем создай файл llm\_service/.env и положи туда:



```text

GIGACHAT\_CREDENTIALS=твой\_ключ\_скопированный

GIGACHAT\_SCOPE=GIGACHAT\_API\_PERS

```

Убедись, что Docker Desktop запущен. Никаких других настроек не требуется — всё остальное собирается автоматически.



\### Как запустить

Открой терминал в папке \\ocr\_llm\_pipeline и выполни:



```bash

docker-compose up -d --build

```

После запуска проверь, что все пять контейнеров работают:



```bash

docker-compose ps

```

Должны быть: ocr\_container, llm\_container, segment\_container, orchestrator\_container, frontend\_container — все со статусом Up.



\## Где лежит фронтенд

Открой браузер и перейди по адресу http://localhost:8080. Это веб-интерфейс, куда можно загружать изображения метрических книг и смотреть результаты.



\### API эндпоинты

Фронтенд отправляет изображения на оркестратор, который координирует всю работу. Но можно вызывать и напрямую:



Оркестратор — POST http://localhost:8003/process (загружаешь файл, получаешь полный результат)



OCR сервис — POST http://localhost:8000/ocr (только распознавание)



LLM сервис — POST http://localhost:8001/correct (только постобработка)



Сегментация — POST http://localhost:8002/segment (только нарезка на ячейки)



Swagger документация доступна по адресам http://localhost:8003/docs, http://localhost:8000/docs и так далее.



\### Как это работает внутри

Когда ты загружаешь изображение через фронтенд, происходит следующее:



Оркестратор сначала отправляет картинку в сервис сегментации. Тот находит линии таблицы, определяет границы строк и столбцов, нарезает изображение на отдельные ячейки. Получается 12 ячеек — 3 строки по 4 столбца (Имя родившегося, Родители, Восприемники, Священник).



Затем оркестратор для каждой ячейки вызывает OCR сервис. Там используется библиотека manuscript-ocr с моделью TrOCR, которая распознает рукописный русский текст. OCR возвращает текст для каждой ячейки.



После того как все ячейки распознаны, оркестратор собирает их в JSON и отправляет в LLM сервис. GigaChat получает этот JSON, исправляет орфографические ошибки, склеивает разорванные слова (например, превращает "государст венным" в "государственным"), убирает мусор типа "Во-", восстанавливает обрубки фамилий "К…" в "Ксения".



Наконец, оркестратор возвращает фронтенду полный JSON с оригинальным и исправленным текстом. Фронтенд показывает таблицу, где для каждой ячейки виден исходный текст и исправленный.



\### Что отвечает за что

ocr\_service — это сервис распознавания. Он работает на порту 8000 и использует модель из библиотеки manuscript-ocr. При первом запуске скачивает веса моделей (около 150 мегабайт), потом работает локально.



llm\_service — постобработка через GigaChat. Порт 8001. Он не просто исправляет орфографию, а именно склеивает разорванные слова, что критично для метрических книг. Требует валидный токен.



segment\_service — нарезка таблицы на ячейки. Порт 8002. Использует детекцию линий через OpenCV. Определяет вертикальные и горизонтальные границы, вырезает каждую ячейку в отдельный файл.



orchestrator\_service — главный координатор. Порт 8003. Он ничего не распознаёт сам, а только вызывает остальные сервисы в правильной последовательности и собирает результаты.



frontend — веб-интерфейс. Порт 8080. Статические файлы, раздаваемые через Nginx.



\## Где сохраняются результаты

Все разрезанные ячейки лежат в папке output/cells/. Там же в JSON-файлах сохраняются метаданные о расположении каждой ячейки. Размеченное изображение с нарисованными линиями таблицы сохраняется как output/segmented\_\*.jpg.



Как проверить, что всё работает

После запуска открой http://localhost:8000/health — должен вернуться {"status": "healthy"}. Так же для портов 8001, 8002, 8003.



Открой фронтенд по адресу http://localhost:8080, загрузи любую фотографию метрической книги, нажми "Обработать". Через минуту должна появиться таблица с распознанным текстом.

Важные моменты

При первом запуске нужен интернет для скачивания весов моделей и для работы GigaChat API. Дальше всё работает локально (кроме GigaChat — он всегда ходит в облако).





Метрика CER считается на фронтенде путём сравнения оригинального и исправленного текста. Она показывает процент изменённых символов. Чем ниже, тем лучше.



В таблице результатов для каждой ячейки виден и оригинальный текст (мелким серым шрифтом), и исправленный (крупным зелёным), если LLM что-то поменял. Если LLM не менял — показывается только оригинал.
